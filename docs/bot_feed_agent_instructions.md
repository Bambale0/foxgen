# Инструкция для Codex-агентов: лента внутри Telegram-бота без Mini App

## Цель

Создать в Telegram-боте полноценную, удобную и логичную ленту работ, похожую по смыслу на Mini App feed, но полностью внутри обычного бота: сообщения, inline-кнопки, deep links, без webview и без Mini App API как обязательной части пользовательского сценария.

Лента должна быть рабочим продуктовым разделом, а не техническим просмотрщиком. Пользователь должен легко:

- смотреть опубликованные генерации;
- переключать режимы ленты;
- лайкать;
- делиться ссылкой;
- повторять или remix/repeat работу;
- открывать профиль автора;
- публиковать свои удачные генерации в ленту и убирать их;
- понимать, что происходит, без инструкций простыней.

## Важные ограничения

- Не ломать существующую Mini App реализацию. Новая работа должна жить в bot-flow и переиспользовать общие функции БД.
- Не менять правила рефералки без отдельной задачи.
- Не писать ad-hoc SQL поверх уже существующих функций, если в `bot/database.py` есть подходящий helper.
- Не делать отдельный web-интерфейс.
- Не добавлять тяжелые изображения в репозиторий.
- Не использовать тесты, которые пишут в `bot.db`. Все автотесты только на временной БД.
- Не показывать пользователю технические формулировки вроде `generation_task_id`, `source_feed_gen_id`, `is_public_feed`.

## Где смотреть текущую реализацию

Основные файлы:

- `bot/handlers/common.py`
  - текущая bot-лента: `_render_feed_carousel`, `_build_feed_keyboard`, `_build_feed_caption`;
  - deep links: `_feed_start_param`, `_feed_share_link`, `_split_feed_deeplink`;
  - callbacks: `menu_feed`, `bf:*`, `bfl:*`, `bfs:*`;
  - `/start feed_..._ref_...` и `/start posts_..._ref_...`.
- `bot/database.py`
  - `get_feed_generations`;
  - `get_user_feed_generations`;
  - `get_feed_generation_card`;
  - `share_to_feed`;
  - `like_feed_generation`;
  - `increment_feed_share`;
  - `add_feed_comment`, `get_feed_comments`;
  - `credit_feed_prompt_repeat`;
  - `create_feed_remix_event`.
- `bot/keyboards.py`
  - главный экран;
  - кнопки публикации результата: `get_image_result_keyboard`, `get_video_result_keyboard`.
- `bot/miniapp.py`
  - богатые сценарии feed/remix/comments, которые можно использовать как продуктовый ориентир, но не тащить web API напрямую в bot-flow.

## Продуктовая модель

Лента в боте должна состоять из нескольких режимов:

- `Новые`: последние опубликованные работы.
- `Топ дня`: свежие работы с высоким score.
- `Топ`: лучшие опубликованные работы в целом.
- `Мои`: опубликованные работы текущего пользователя.
- `Автор`: профильная лента конкретного автора по referral code/deep link.

Текущий код уже использует короткие source-коды:

- `r` для recent;
- `d` для top_day;
- `t` для top;
- `m` для профиля автора.

Можно сохранить эту схему callback-данных, но сделать интерфейс более цельным.

## Основной пользовательский флоу

### 1. Вход в ленту

Пользователь нажимает `🖼 Лента` в главном меню.

Ожидаемое поведение:

- бот показывает первый пост из режима `Новые`;
- если постов нет, показывает аккуратное пустое состояние;
- сообщение должно быть media-сообщением с image/video preview, подписью и inline-клавиатурой;
- переключение карточек должно редактировать текущее сообщение, а не плодить новые, где это возможно.

### 2. Просмотр карточки

Карточка должна показывать:

- тип: фото или видео;
- модель;
- автора;
- позицию `N/M`;
- счетчики: лайки, повторы/remix, ссылки/шеры;
- для нескольких изображений: `Фото X/Y`;
- краткую подпись без prompt-простыни.

Не перегружать caption. Prompt можно показывать отдельной кнопкой, если это безопасно и разрешено.

### 3. Навигация

Обязательные кнопки:

- `◀️` / `▶️` для карточек;
- `🆕 Новые`;
- `🔥 Топ дня`;
- `⭐ Топ`;
- `👤 Автор` или `Мои`, если применимо;
- `🏠 Главное меню`.

Для мульти-изображений:

- `◀️ Фото`;
- `Фото X/Y`;
- `Фото ▶️`.

### 4. Действия с карточкой

Обязательные действия:

- `❤️` лайк;
- `🔗 Ссылка` или `🔗 Скопировать ссылку`;
- `🔁 Повторить`;
- `🧬 Remix` для feed-based генерации, если исходник подходит;
- `👤 Автор`;
- `💬 Комментарии`, если реализуются комментарии.

Важно: если Telegram-кнопка с `copy_text` недоступна или есть риск совместимости, оставлять fallback-кнопку `🔗 Ссылка`, которая отправляет пользователю deep link отдельным сообщением.

### 5. Публикация в ленту

После успешной генерации уже есть кнопки:

- `🖼 В ленту`;
- `🎞 В ленту`;
- `🗑 Убрать из ленты`.

Нужно сделать флоу аккуратным:

- при публикации показывать короткое подтверждение;
- после публикации дать кнопки `Открыть в ленте`, `Скопировать ссылку`, `Главное меню`;
- при снятии с публикации также обновлять клавиатуру результата.

## Deep links и рефералка

Deep link для карточки должен сохранять реферальный код автора:

```text
https://t.me/<bot_username>?start=feed_<generation_id>_ref_<author_referral_code>
```

Для профиля автора:

```text
https://t.me/<bot_username>?start=posts_<profile_referral_code>_ref_<author_referral_code>
```

Требования:

- при открытии deep link сначала создать/получить пользователя;
- активировать рефералку, если пришел `_ref_...`;
- потом показать нужную карточку или профильную ленту;
- если карточка не найдена, показать понятное сообщение и кнопку в обычную ленту;
- не показывать пользователю внутренние ID.

## Remix/repeat внутри бота

Минимально ожидаемое поведение:

- `🔁 Повторить` запускает уже существующий повтор генерации по `task_id`, если такой flow уже есть.
- `🧬 Remix` должен брать опубликованную карточку как source и запускать создание новой генерации с `source_feed_gen_id`.
- Если для remix нужен пользовательский референс, бот должен попросить фото/референс в рамках FSM.
- Если у пользователя не хватает бананов, показать баланс и кнопку пополнения.
- При успешном remix сохранить связь с исходником, чтобы счетчик повторов/remix рос и работали выплаты автору, если они предусмотрены.

Не пытаться вручную копировать сложную логику из Mini App целиком. Лучше вынести общую доменную функцию в сервис/helper и вызвать ее и из Mini App, и из bot-flow.

## Комментарии

Комментарии можно делать вторым этапом, но инструкция для реализации:

- кнопка `💬 Комментарии`;
- показывать последние 5-10 комментариев;
- кнопки `✍️ Написать`, `🔄 Обновить`, `🔙 К посту`;
- ввод комментария через FSM;
- ограничение длины, например 300 символов;
- HTML escape обязательно;
- добавить антиспам: хотя бы ограничить частоту или повтор одинакового текста.

Использовать существующие функции:

- `get_feed_comments`;
- `add_feed_comment`.

## Мои публикации и профиль автора

Нужно добавить удобный путь к своим работам:

- из ленты кнопка `Мои`;
- из главного меню можно добавить отдельный быстрый вход позже, если нужно;
- в режиме `Мои` показывать только опубликованные работы пользователя;
- на карточках автора показывать `👤 Автор`;
- `👤 Автор` открывает профильную ленту автора.

Для автора использовать `get_user_feed_generations(author.id, ...)`.

## Callback data

Callback data должна быть короткой. Telegram ограничивает ее размер.

Рекомендуемая схема:

- `bf:<source>:<index>:<photo_index>` — обычная лента;
- `bfp:<profile_code>:<index>:<photo_index>` — профиль автора;
- `bfl:<gen_id>:<source>:<index>:<photo_index>` — лайк в обычной ленте;
- `bflp:<gen_id>:<profile_code>:<index>:<photo_index>` — лайк в профиле;
- `bfs:<gen_id>` — получить ссылку;
- `bfc:<gen_id>` — комментарии;
- `bfca:<gen_id>` — добавить комментарий;
- `bfr:<gen_id>` — remix;
- `bfm:<index>:<photo_index>` — мои публикации, если не хватает текущих схем.

Перед добавлением новых callback убедиться, что нет конфликтов с существующими.

## UX-требования

- Лента должна работать одной карточкой/сообщением, насколько позволяет Telegram.
- После действия `лайк` карточка должна обновиться на месте.
- После `ссылка` пользователь должен получить ссылку без потери текущей карточки.
- После ошибки загрузки изображения использовать placeholder, а не падать.
- Не отправлять пользователю длинные технические ошибки.
- Пустые состояния должны подсказывать следующее действие:
  - в общей ленте: “Пока нет опубликованных работ”;
  - в моих: “Опубликуйте удачную генерацию кнопкой «В ленту»”.
- Стараться не создавать больше одного нового сообщения на один клик.

## Медиа и Telegram-ограничения

Текущая реализация уже умеет:

- скачивать preview;
- сжимать фото до лимита Telegram;
- использовать placeholder.

Сохранять этот подход. Для видео:

- если видео URL Telegram может отправить как video, использовать video;
- если нет, показывать thumbnail/placeholder и кнопку `📥 Скачать видео`;
- не пытаться всегда загружать тяжелое видео как файл.

## Безопасность и приватность

- В ленту попадают только явно опубликованные генерации (`is_public_feed`).
- Не публиковать prompt, если он скрыт или относится к remix, где prompt_actions запрещены.
- Не показывать личные внутренние ID.
- Все пользовательские строки в caption и комментариях HTML-экранировать.
- Не публиковать неуспешные/failed/pending задачи.
- Убрать из ленты может только владелец или админ.

## Что проверить вручную

Smoke-сценарии:

1. Открыть `🖼 Лента`.
2. Переключить `Новые`, `Топ дня`, `Топ`.
3. Пролистать 3-5 карточек вперед/назад.
4. Открыть карточку с несколькими фото и пролистать фото.
5. Поставить лайк, убедиться, что счетчик обновился.
6. Нажать ссылку/копирование, открыть deep link с другого аккаунта.
7. Проверить, что deep link показывает нужную карточку.
8. Проверить, что deep link с `_ref_...` не ломает рефералку.
9. Опубликовать свою генерацию в ленту.
10. Открыть ее из `Мои`.
11. Убрать из ленты.
12. Попробовать открыть снятую с публикации карточку по deep link.
13. Проверить пустое состояние у пользователя без публикаций.
14. Проверить поведение при недоступном image URL.

## Автотесты

Обязательно добавить или обновить тесты на временной БД:

- выборка ленты возвращает только опубликованные completed-задачи;
- лайк идемпотентен: повторный лайк тем же user_id не увеличивает счетчик;
- share увеличивает `shares_count`;
- deep link parser корректно разбирает `feed_<id>_ref_<code>`;
- профильная лента возвращает только работы автора;
- снятая с публикации карточка не показывается в публичной ленте;
- комментарии HTML-экранируются, если добавляются;
- callback handlers не падают на отсутствующем/удаленном посте.

Запускать минимум:

```bash
pytest -q tests/test_prompt_feed_database.py tests/test_referral_system.py tests/test_miniapp_referrals.py
python -m py_compile bot/database.py bot/handlers/common.py bot/keyboards.py
```

Если добавлены новые bot-flow тесты, включить их в команду.

## Критерии готовности

Фича считается готовой, когда:

- пользователь может пользоваться лентой только в Telegram-боте;
- есть понятные режимы просмотра;
- лайки/шеры/профиль автора работают;
- deep links работают;
- публикация/снятие публикации работает из результата генерации;
- рефералка через deep link не сломана;
- нет записи тестов в `bot.db`;
- регрессионные тесты проходят;
- сервис `banano-kling.service` после деплоя активен.

## Важный стиль реализации

Делать небольшими шагами:

1. Стабилизировать текущую bot-карусель.
2. Добавить “Мои” и профиль автора.
3. Улучшить публикацию/снятие.
4. Добавить комментарии.
5. Добавить remix/repeat, если хватает контекста и уже понятен текущий generation flow.

Не начинать с большого переписывания `common.py`. Если функция становится слишком большой, вынести feed-логику в отдельный модуль, например `bot/handlers/feed.py`, но только если это не ломает роутинг и импорты.
